GEOAPIFY LIVE SEARCH PATCH
==========================

This patch updates only these existing project files:
- app.py
- app/services/place_service.py
- app/services/hotel_service.py
- app/services/restaurant_service.py
- static/js/places.js
- static/css/places.css
- static/js/planning.js
- static/js/itinerary.js

IMPORTANT:
1. Keep your existing .env file private. This patch does not contain it.
2. Confirm your project-root .env contains:
   GEOAPIFY_API_KEY=your_existing_key
   Do not put quotes around the value unless your key itself contains quotes.
3. From the project root, back up the affected files:
   mkdir -p backup_before_geoapify_patch
   cp app.py app/services/place_service.py app/services/hotel_service.py app/services/restaurant_service.py static/js/places.js static/js/planning.js static/js/itinerary.js static/css/places.css backup_before_geoapify_patch/
4. Extract this ZIP directly into the existing AI_Travel_Tourism project root, preserving folders.
   Do not extract it into a new nested AI_Travel_Tourism folder.
5. Restart Flask from the project root:
   source venv/bin/activate
   python app.py
6. Hard refresh the browser with Ctrl+Shift+R.

WHAT CHANGES:
- Attraction search uses Geoapify Places API, with geocoding restricted to India.
- Results are separated into Famous Places and Beautiful & Scenic Places; famous places are prioritized.
- Real photos are enriched from Wikipedia/Wikimedia Commons where available. The first cards load eagerly.
- The manually curated city/attraction fallback catalogue is removed.
- places.js is the only tourist-place loader; duplicate loading is removed from planning.js.
- Hotel and restaurant nearby results use Geoapify, not Overpass.
- The Mumbai-only hard-coded hotel/restaurant fallback is removed.
- Existing favorites, add-to-trip, details modal, itinerary and profile logic are otherwise retained.

LIMITATIONS:
- Photos are retrieved from Wikipedia/Wikimedia Commons when matching media exists. Wikimedia does not have a verified photo for every mapped place, so a genuine photo cannot be guaranteed for every single result; no unrelated/fabricated image is inserted. Famous places are prioritized for photo lookup.
- Geoapify/OpenStreetMap data may not include ratings, phone numbers, websites, or every local business. Missing fields are left blank rather than invented.
- Geoapify quotas and service availability apply. This patch does not guarantee that
  every destination has mapped listings.
- The Geoapify API key stays server-side; never place it in JavaScript or upload .env.

TEST:
- Open /planning with a destination in India.
- In browser DevTools > Network, verify only one /api/places request is made on initial load.
- Open /api/nearby?destination=Hyderabad in the browser to inspect live hotels/restaurants.
- If requests fail, check Flask terminal for GEOAPIFY errors and verify the key is active.
